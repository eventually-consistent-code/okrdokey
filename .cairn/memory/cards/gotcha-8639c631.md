Playwright shared-server state races ESCALATE beyond unique naming (extends gotcha-88c73c8a): with parallel workers and instance-global state (cycles), any first-run/empty-state assertion ("No cycles yet.") is unwinnable for every spec except whichever signs up first — three specs asserted it, local runs passed on timing luck for days, and CI failed for real (twice — the second red run went unnoticed behind a sampling error). The durable fix class: (1) workers: 1 in playwright.config so ordering is deterministic; (2) exactly ONE spec — the first in run order — owns any empty-state/first-run assertion, all others navigate directly to the page they need; (3) unique global-resource names per spec and pinned pickers remain necessary but are NOT sufficient. Unique names fix collisions; they cannot fix assertions about global emptiness.
